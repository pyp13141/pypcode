## 2026-10-11 修复记录（47/49 → 51/51）

交接时的 47/49 基线**没有经受住真实 SMTP 上线的考验**：重新全量跑实为 15/49——冒烟脚本靠
journalctl 的 `EMAIL-MOCK] to=... code=...` 日志行取验证码，真实 SMTP 上线后验证码只经邮件送达，
取码为空 → 邮箱登录失败 → 用户 A 令牌为空 → **34 项级联失败**。本轮修复：

1. **邮箱段改为真实链路**：发码到 126 发件邮箱本身 → 用 IMAP（imap.126.com:993，NetEase 要求登录后发
   `ID` 指令，imaplib 需先注册）从收件箱取最新验证码邮件的主题码 → 登录。只认发码时刻之后的邮件（防取到
   上一轮旧码）。这同时把"邮件真实送达"变成冒烟断言——比原先（日志取码）更强。**不违反 AUTH_CODE_ECHO
   禁令**（读平台自己的收件箱 ≠ 接口直显）。
2. **riskTip 断言修复**：原脚本请求了不存在的 `GET /market/deals/:id`（404 空信封）导致 conversationId
   为空；契约上 conversationId 只随 `POST /market/deals` 返回，改为从创建响应取，并补"交易会话随建返回"断言。
3. **幂等键按次隔离**：accept/visit/complete/review 的固定键（smoke-accept-1 等）改为带 `$RUN_ID`——
   幂等存储跨运行持久，固定键第二轮必 409 `IDEMPOTENCY_KEY_CONFLICT`。
4. **删除死代码**：原 57 行微信登录 JSON 引号未转义（生成无效 JSON），其 token 从未被使用。
5. **CARE_FIRST 断言**：交接基线中它的失败是 M6 徽章钩子补全前的残留（D-015 #3），钩子补全后自然通过。

## 运行须知

- 两次运行间隔 ≥1 分钟（126 对同一收件邮箱限流 1 次/分钟）；每轮消耗 1 封真实验证码邮件。
- 幂等键带 `$RUN_ID`，可任意重复运行；每轮在库中留一个冒烟用户与一条交易/订单数据（业务上无害）。
- 需 root（读 `/etc/pet-neighbor/api.env` 的 `SMTP_*` 与 DB 密码文件）。
